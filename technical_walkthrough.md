> [!IMPORTANT]
> **This document describes the state of the project BEFORE the data-pipeline fix.**
> The discrepancies it catalogues in Section 4 ("Hardcoded Numeric Literals"),
> Section 8 ("Label vs Code Audit") and Section 9 ("Known Limitations") have since
> been fixed. Line numbers and code excerpts below no longer match the sources.
>
> What changed:
> - The Unit 1 imputation sparkline read `.time` / `.value` / `.is_missing` off a
>   flat numeric array and rendered nothing; it now reads the array positionally.
> - The Unit 1 polyfit sparkline plotted the 100 fitted-curve values against a
>   category axis of 300 randomly ordered hours; both series now share one linear
>   hour axis.
> - The covariance scatter panel reported the all-column complete-case count for
>   every pair, and fabricated sin/cos points for any pair missing from
>   `scatter_data` (including the whole heatmap diagonal). It now reports the
>   pairwise-complete count and plots real readings for every cell.
> - `KNNImputer(n_neighbors=3)` is now `n_neighbors=5`, matching every `k=5` label.
> - Mean/Median MAE was measured over all holdout values while KNN MAE was measured
>   over only the 15% masked cells of a 3-column matrix. All three are now scored on
>   the same masked cells of the same 9-channel matrix.
> - The imputation panel showed the mean of three MAEs measured in mg/m³, ppb and
>   µg/m³; it now shows the plotted column's own MAE.
> - `StandardScaler` was fitted on the full matrix before the train/test split in
>   both Ridge and SVM; it is now fitted on the training split only.
> - The SVM boundary plot was labelled "2D PCA" but used two raw channels, had no
>   axes, and always drew the RBF grid regardless of the selected kernel. It is now
>   correctly labelled, axed, and computed per kernel.
> - The OLS collinearity readout, the "RBF Kernel Accuracy", the top correlated
>   pair, the test-sample counts and the y = x reference line were hard-coded; all
>   are now derived from the results files.
> - Polynomial `curve_points` stored `x` rounded to 2 dp but `y` evaluated at the
>   unrounded `x`, so each point sat slightly off its own label.
> - The AQI gauge displayed a synthetic 40–185 sine sweep labelled as live
>   telemetry. It now steps through the real EPA CO index of the CSV's 8-hour
>   running means, and reads `--` if the data file is unavailable.
>
> `tests/verify_graph_data.mjs` now guards all of the above against the raw CSV.

def parse_hour(t_str):
    if pd.isna(t_str):
        return np.nan

## 5. UNIT 1 — EXACT PARAMETERS

### 5.1 Imputation

**Columns imputed:**
```python
# generate_all_results.py:123
imp_cols = ['CO(GT)', 'NOx(GT)', 'NO2(GT)']
```

**KNNImputer n_neighbors:**
```python
# generate_all_results.py:140
knn_imputer = KNNImputer(n_neighbors=3)
```

> [!WARNING]
> The code passes `n_neighbors=3`, but all description text now says `k=5` (after the edit we made earlier). **This is still a label-vs-code mismatch**, just in the opposite direction from the original — see Section 8.

**KNN feature matrix:**
```python
# generate_all_results.py:142
knn_features = ['CO(GT)', 'PT08.S1(CO)', 'C6H6(GT)', 'PT08.S2(NMHC)',
                'NOx(GT)', 'PT08.S3(NOx)', 'NO2(GT)', 'T', 'RH']
```

**Masking strategy:** All three target columns are masked **simultaneously** via a random boolean mask across the entire `eval_masked` matrix:
```python
# generate_all_results.py:146-148
eval_masked = eval_sample.copy()
mask = np.random.RandomState(42).rand(*eval_masked.shape) < 0.15
eval_masked[mask] = np.nan
```

**Holdout fraction:** Not a fraction of the full dataset. Instead, up to 1500 rows are sampled from the already-complete rows (all three imputed columns non-NaN), then 15% of cells within that sample are artificially masked:
```python
# generate_all_results.py:128-129
df_eval = df[imp_cols].dropna().copy()
eval_sample = df_eval.sample(n=min(1500, len(df_eval)), random_state=42).copy()
```

**Random seed:** `42` (for sampling at line 129, and for mask generation at line 147)

**MAE computation:**
```python
# generate_all_results.py:152-154 (KNN example)
for c in imp_cols:
    diffs = np.abs(knn_eval_imputed.loc[mask[:, imp_cols.index(c)], c]
                   - eval_sample.loc[mask[:, imp_cols.index(c)], c])
    mae_knn[c] = round(float(diffs.mean()), 3) if len(diffs) > 0 else 0.85
```

MAE is computed **only on the artificially masked cells** (not on all cells), per column. The overall MAE is the arithmetic mean of the three per-column MAEs:
```python
# generate_all_results.py:158
overall_mae_knn = round(float(np.mean(list(mae_knn.values()))), 3)
```

**For Mean/Median imputation**, MAE is computed differently — it measures the absolute error of substituting the global mean/median for every value in the eval_sample (even non-masked values):
```python
# generate_all_results.py:136-137
mae_mean = {c: round(float(np.mean(np.abs(eval_sample[c] - means[c]))), 3) for c in imp_cols}
mae_median = {c: round(float(np.mean(np.abs(eval_sample[c] - medians[c]))), 3) for c in imp_cols}
```

> [!CAUTION]
> The Mean/Median MAE is computed on **all** 1500 holdout values (measuring the error of replacing every known value with the global statistic), while the KNN MAE is computed on **only the 15% masked cells**. These are fundamentally different evaluation protocols, making the MAE values across methods **not directly comparable**.

## 9. KNOWN LIMITATIONS

### Data Leakage
- **StandardScaler is fit on the entire dataset** before train/test split in both Ridge ([line 309](file:///c:/Users/HP/Desktop/ML PROJECT/scripts/generate_all_results.py#L309)) and SVM ([line 405](file:///c:/Users/HP/Desktop/ML PROJECT/scripts/generate_all_results.py#L405)). This leaks test set statistics into training.

### Inconsistent MAE Evaluation
- Mean/Median MAE is computed over **all** holdout values (measuring distance from every known value to the global mean/median). KNN MAE is computed over only the **15% artificially masked** values. This makes the three methods' MAE values not directly comparable.

### n_neighbors=3 vs k=5 Mismatch
- Every text label now says `k=5` but the Python code still passes `n_neighbors=3`. Either the code or all labels need updating.

### No PCA — Mislabeled Decision Boundary
- The "2D PCA Decision Boundary" uses raw features `PT08.S1(CO)` and `PT08.S2(NMHC)`, not PCA components. The HTML note partially acknowledges this but still calls it PCA.

### Separate 2D Model for Boundary Plot
- The decision boundary is drawn by a **different SVM model** (`clf_2d`) fitted on only 2 unscaled features from a 2000-row subsample. It has no relationship to the reported accuracy/confusion matrix numbers, which come from the full 6-feature scaled model.

### Hardcoded Stale Values
- Several numeric literals in HTML and JS are baked-in approximations that don't update if the Python script is re-run (RBF accuracy "81.8%", coefficient values in the OLS diagnostic text, correlation "r=0.90").

### No Version Pinning
- Chart.js is loaded via unpinned CDN (`/npm/chart.js`), and Python dependencies have no `requirements.txt`. A future Chart.js breaking change could silently break the site.

### Sampling
- Scatter charts show 150–300 randomly sampled points, not the full dataset. The imputation timeline shows a fixed window of 400 consecutive rows (`iloc[200:600]`).

### KNN Imputer Fit-Transform Double Call
- The `knn_imputer` is `fit_transform`'d once on the eval sample ([line 150](file:///c:/Users/HP/Desktop/ML PROJECT/scripts/generate_all_results.py#L150)) and then `fit_transform`'d again on the 400-row visualization window ([line 174](file:///c:/Users/HP/Desktop/ML PROJECT/scripts/generate_all_results.py#L174)). The second call fits an entirely new model, so the MAE metric and the visualized chart come from **different KNN models**.

### Deterministic on Reload
- All values are precomputed in JSON. Reloading the page does not change any metrics. Only the AQI gauge animation varies (purely cosmetic time-based sweep). Changing the seed and re-running `generate_all_results.py` would change all metrics.

### No NMHC(GT) Usage
- The column `NMHC(GT)` is present in the dataset but is never used in any analysis (it has ~90% missing values in the original UCI dataset).
